## 0. 术语与约定

| 术语 | 含义 |
|------|------|
| 面试记录（Interview） | 一次导入的面试会话，含元信息、原始转写文本、结构化问答 |
| 问答条目（QAItem） | 单场中的一问一答（含追问链），忠实原文 + 独立优化建议/批注 |
| 知识库条目（KnowledgeEntry） | 跨场按知识点/问法聚合的面经沉淀，含频次与出处 |
| 专题 | 知识库中单独成块的总结区：**自我介绍 / 个人发展 / 反问环节** |
| 非 AI 模式 | 不调用大模型，仅规则切分 + 本地相似判定；AI 相关能力自动降级并明确提示 |
| AI 模式 | 调用已配置的大模型：抽取、角色推断、相似判定、模拟面试生成等 |
| 三红线 | R1 角色归属不靠猜（有标签直读、无标签可推断但可改）；R2 提取忠实原文、优化建议独立成栏；R3 统一 schema、按知识点去重合并、统计频次 |

## 1. 范围

**本轮新增/变更范围**
1. 全局 UI 规范落地：所有页面"简洁明了、布局美观"。
2. 导入面试：新增地点、时间、期望薪资、时长等字段；标题自动生成且可手动输入。
3. 面试记录：记录留存与查看；每题提供"隐藏/显示答案"开关。
4. 知识库：三个专题单独总结；其余按关键词分类；记录询问频次；相似问题识别关联并可对比查看。
5. 模拟面试：整场模拟 / 简历导入 + 题库随机 + AI 生成；面试官语音包（开源方案）。
6. 设置：主题切换、大模型 API 配置、AI/非 AI 模式切换。

**不在本轮范围**：多用户/登录、云端同步、移动端 App、录音采集与自动转写（仍只消费转写文本）。

**红线约束**：本轮所有改动不得破坏三红线；其中"反问环节"涉及一次角色方向扩展（见 FR-03.4 与开放问题 Q5）。

## 2. 全局 UI/UX 规范（GLOBAL-UI）

### 2.1 设计原则
1. **一屏一事**：每个页面只承担一个主要任务，主操作按钮唯一且突出。
2. **信息分层**：默认只展示摘要（标题/时间/频次/状态），细节按需展开（折叠、抽屉、下钻页）。
3. **克制装饰**：不用花哨动效与大面积高饱和色；用留白、字号层级、细边框区分结构。
4. **状态可见**：任何操作有即时反馈（保存成功/失败、加载中、空状态引导）。
5. **一致性**：同类信息用同一组件与位置呈现；按钮语义固定（主=蓝实心，次=描边，危险=红）。

### 2.2 视觉规范（Design Token）
| 项目 | 规范 |
|------|------|
| 布局 | 居中容器最大宽 1080px（内容页）/ 1200px（列表页）；左右留白 ≥ 16px；卡片内边距 16–20px |
| 间距 | 8px 基准栅格：4/8/12/16/24/32；区块间距 24px，卡片间距 14px |
| 字体 | 系统字体栈（-apple-system / Segoe UI / Microsoft YaHei）；正文 14px/1.6，标题 20–24px，辅助 12.5px |
| 颜色 | 品牌蓝 `#2563eb`；语义色 成功 `#16a34a`、提醒 `#d97706`、危险 `#dc2626`；中性灰阶 4 级 |
| 圆角/阴影 | 卡片 12px 圆角 + 1px 边框 + 极轻阴影；按钮 8px 圆角 |
| 主题 | 浅色（默认）/ 深色 / 跟随系统；全部颜色走 CSS 变量，禁止硬编码色值 |
| 图标 | 优先文字标签 + 少量线性图标；不使用 emoji 作为功能图标 |
| 响应式 | ≥1024px 双栏；768–1024px 单栏；<768px 单栏 + 表格式布局转卡片 |
| 表格 | 表头浅底、行分隔线、悬停高亮；操作列固定最右；>20 行分页或虚拟滚动 |
| 空状态 | 一句话说明 + 一个主操作按钮（如"导入第一场面试"） |
| 反馈 | 顶部轻提示条（成功/失败）；破坏性操作用确认弹层 |

### 2.3 导航信息架构
```
顶栏：AI_Review ｜ 工作台 ｜ 导入面试 ｜ 面试记录 ｜ 知识库 ｜ 模拟面试 ｜ 设置 ｜（右侧）AI/非AI 模式徽标
```
- 导出入口保留在"面试记录详情"与"知识库"页内。
- 移动端折叠为汉堡菜单。

## 3. 功能需求

### FR-01 导入面试（优先级 P0）

**目标**：一次性录入本次面试元信息与转写文本，字段尽量全但**全部可为空**，不阻塞导入。

**字段规格**

| 字段 | 键名 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|------|
| 面试标题 | `title` | 文本 | 否 | 自动生成（可改） | 自动生成规则见 FR-01.2；用户一旦手动编辑则以手动值为准 |
| 面试公司 | `company` | 文本 | 否 | 空 | |
| 面试岗位 | `position` | 文本 | 否 | 空 | |
| 面试地点 | `location` | 文本 | 否 | 空 | 支持"线上/远程"等自由文本 |
| 面试时间 | `interview_at` | 日期时间 | 否 | 当前时间 | 精确到分钟；支持仅填日期 |
| 期望薪资 | `expected_salary` | 文本 | 否 | 空 | 建议自由文本（如 "25-30K×14"）；是否结构化见 Q2 |
| 时长 | `duration_minutes` | 整数（分钟） | 否 | 空 | **整场面试时长**；非数字输入时提示并允许留空 |
| 面试类型 | `interview_type` | 枚举 | 否 | 综合面 | 保留现有：技术/行为/HR/综合/模拟 |
| 转写文本 | `text` | 长文本 | 是 | — | 唯一必填项（可粘贴或上传 .txt/.md） |

**FR-01.1 交互流程**
1. 进入"导入面试"页 → 表单区（元信息）在上、"转写文本"区在下。
2. 文本区支持：粘贴、上传文件、"载入示例"。
3. 点击"识别说话人与格式" → 展示识别出的说话人及默认角色（现有能力）→ 用户确认/纠正。
4. 点击"创建并解析" → 解析入库 → 跳转该面试记录详情，并提示"已提取 N 题（其中 M 题待确认）"。

**FR-01.2 标题自动生成规则（按优先级取第一个非空组合）**
1. `公司-岗位-YYYY-MM-DD HH:mm`
2. `公司-岗位-YYYY-MM-DD`
3. `公司-面试-YYYY-MM-DD`
4. `面试-YYYY-MM-DD HH:mm`
5. 全部为空 → `未命名面试-YYYYMMDD-HHmm`
6. 标题输入框旁提供"按规则重算"按钮；手动编辑后不再自动覆盖。

**FR-01.3 验收标准**
- [ ] 所有元信息字段留空时仍可成功导入并正常解析。
- [ ] 自动标题符合规则且可被手动覆盖；覆盖后新增/重算不会回滚用户输入。
- [ ] 时长填非数字（如 "一小时"）给出明确提示，不阻断提交（按留空处理）。
- [ ] 面试时间字段渲染为日期时间选择器，展示于记录列表与详情页。
- [ ] 移动端表单单列排布，输入框不横向溢出。

### FR-02 面试记录（列表 / 查看 / 答案隐藏）（优先级 P0）

**目标**：所有导入的面试自动留存于"面试记录"页，可检索、可进入查看；复习时能一键隐藏答案自测。

**FR-02.1 记录列表页**
- 顶部：统计条（总场次 / 累计题目 / 待确认题目 / 覆盖公司数）。
- 工具条：关键词搜索（标题/公司/岗位）、按时间/公司筛选、排序（时间倒序默认 / 题数 / 未确认优先）。
- 记录卡片（替代现有密集表格，更易读）：
  ```
  ┌──────────────────────────────────────────────────────────┐
  │ 字节跳动-后端工程师-2024-05-20 14:30      [技术面] [已入库] │
  │ 地点：北京·海淀 ｜ 时长：58 分钟 ｜ 期望：25-30K          │
  │ 题目 12 题 · 待确认 2 · 已入库 10        [查看] [导出 .md] │
  └──────────────────────────────────────────────────────────┘
  ```
- 空状态："还没有面试记录 → [导入第一场面试]"。

**FR-02.2 详情查看页（原"问答列表"升级）**
- 头部：面试元信息（标题、公司/岗位、地点、时间、时长、期望薪资、类型、解析方式、角色映射徽标）+ 进度与操作（全部确认、整场入库、导出）。
- 问题列表：默认显示"问题 + 状态 + 知识点 + 回答摘要（截断）"。
- **每题右侧"隐藏答案 / 显示答案"开关**（FR-02.3）。
- 支持进入单题复盘（保留现有忠实原文 + 优化建议 + 批注能力）。

**FR-02.3 答案隐藏交互（核心新增）**
- 每题目行右侧提供切换按钮：`隐藏答案` ⇄ `显示答案`，点击即时切换（无页面刷新）。
- 默认状态：**显示**（避免新用户困惑）。
- 顶部提供批量操作：`全部隐藏（复习模式）` / `全部显示`。
- 隐藏态样式：答案区替换为占位条"答案已隐藏（点击显示）"，不泄漏字数与首字。
- 状态记忆：每场面试的隐藏偏好持久化（建议 `localStorage` 按 interview_id + qa_id 记录；是否需要跨设备/服务端存储见 Q9，默认本地）。
- 复习模式（可选 P1）：进入后自动全部隐藏，并支持"逐题翻开 → 自评标记（会/不会）"。

**FR-02.4 验收标准**
- [ ] 导入后的面试可在记录页按时间倒序检索到，并显示全部元信息。
- [ ] 每题独立隐藏/显示答案，互不影响；批量按钮作用于当前面试全部题目。
- [ ] 隐藏状态在刷新页面后保持（localStorage）。
- [ ] 隐藏态不通过 DOM 文本泄漏答案内容（占位文案实现）。
- [ ] 记录页在 10 场/500 题规模下渲染 ≤ 300ms。

### FR-03 知识库（专题 / 分类 / 频次 / 相似关联 / 对比）（优先级 P0，相似对比为 P0/P1 混合）

**目标**：把跨场沉淀的问题组织为可复习的知识体系：三个专题单独总结，其余按关键词分类，显示频次，相似问题相互关联并可对比多次作答。

**FR-03.1 页面结构**
```
知识库
├─ ① 专题区（置顶，单独总结）
│   ├─ 自我介绍      ：汇总历史所有"自我介绍"问答，展示多版本回答对比、演进与优化建议
│   ├─ 个人发展      ：职业规划 / 优缺点 / 离职原因 / 求职动机 等归类汇总
│   └─ 反问环节      ：我向面试官提出的问题汇总（角色反转，见 FR-03.4）
└─ ② 分类区（关键词分类）
    ├─ 项目经历  ├─ 技术栈（Java/JVM/缓存/数据库/网络/算法…）  ├─ 团队协作
    ├─ 系统设计  ├─ 行为问题（STAR）  └─ 其他
```

**FR-03.2 分类与关键词规则**
- 在现有 `_CATEGORY_KEYWORDS` 基础上补齐：**团队协作**（团队/协作/沟通/跨部门/配合/冲突处理）、**技术栈**聚合视图（把 JVM/缓存/数据库/网络/算法等二级知识点归入"技术栈"大类）、**项目经历**（项目/负责/难点/成果）、**个人发展**（职业规划/优缺点/离职/求职动机/成长）、**反问环节**（"你有什么想问的"/我提出的问题）。
- 分类结果允许人工修正（现有能力保留），修正后写回 `categories`。
- 分类层级：一级分类（上表 6 类 + 3 专题）→ 二级知识点（现有 Category），页面上按一级分组、二级卡片展示。

**FR-03.3 频次统计**
- 每个二级知识点显示：**被问次数**、最近被问时间、覆盖面试场次、变体问法数。
- 每个一级分类显示：累计被问次数、条目数、覆盖场次。
- 每个专题显示：累计出现次数、涉及场次、最新一次时间。
- 数据来源：`entries.ask_times` / `source_qa_ids`（现有 R3 计数），无需重复计数。

**FR-03.4 相似问题识别与关联**
- 判定目标：同一意图的不同问法（如"讲讲缓存实现" ≈ "缓存是怎么做的？"）自动互相关联。
- **方案分层（推荐组合）**：
  1. **规则层（非 AI 模式可用，零依赖）**：归一化键相同 → 直接同一；否则计算字符级相似度（difflib 比率）+ 关键词重合度（中文 2-gram Jaccard），综合分 ≥ 阈值（建议 0.72，可配置）判为相似；对"技术名词 + 动作词"命中加权。
  2. **AI 层（AI 模式增强）**：把候选对（规则分 0.5–0.72 的灰区）交 LLM 判定"是否同一问题"，输出布尔 + 理由；结果缓存，避免重复计费。
  3. **向量层（P2 备选）**：本地 embedding 近似检索，网络受限环境暂缓（见 Q3）。
- 关联结果持久化：新增 `similar_pairs` 表（`qa_a_id, qa_b_id, entry_a_id, entry_b_id, score, method, created_at`）。
- 展示：知识点卡片右上角显示"相似 N 条"徽标；点击进入**对比页（FR-03.5）**。
- 人工操作：支持"确认为同一问题（合并为一组）/ 取消关联 / 手动建立关联"，用户判定优先级最高。

**FR-03.5 对比查看页**
- 进入方式：知识点卡片"相似 N 条 → 查看对比"。
- 布局：左列为"问题变体清单"（含频次、时间），右侧为**并列对比区**：
  - 每次作答一行/一列，展示：面试来源（公司/时间）、忠实原文回答（可折叠）、优化建议、批注、自评/标记；
  - 顶部汇总：总频次、时间跨度、平均长度、高频关键词差异（可选）；
  - 支持"标为最佳作答"（写入 `entries` 参考字段，P1）。
- 红线保持：对比页所有"回答"仍来自忠实提取，优化建议/批注独立成列，禁止混写。
- 空态/单条态：仅一条时提示"暂无相似问题，已显示本条目历史作答"。

**FR-03.6 反问环节（角色反转，需确认）**
- 面试末段常见"你有什么想问我们的？"——此时**提问方是我、回答方是面试官**。
- 数据表示：不新增实体；在 `qa_items` 增加 `direction` 字段（`normal` 提问=面试官 / `reverse` 提问=我），抽取时按标签判定，绝不猜测。
- 知识库"反问环节"专题汇总所有 `direction=reverse` 的问答，供下次面试复用。
- 需用户确认（Q5）：是否采纳该反转建模。

**FR-03.7 验收标准**
- [ ] 三个专题在知识库页顶部独立成块，内容来自跨场聚合数据。
- [ ] 其余问题按一级分类分组展示，并显示二级知识点与频次。
- [ ] 相似问题自动关联，给出相似度与判定方式（规则/AI/人工）标识。
- [ ] 点击"查看对比"可并列查看同一问题的多次作答，且能看到来源面试与时间。
- [ ] 非 AI 模式下相似关联仍可用（规则层），不出现"必须配置 API"的硬阻断。
- [ ] 全部计数与现有 R3 口径一致（不出现两套频次数字）。

### FR-04 模拟面试（优先级 P1）

**目标**：用已有题库 + AI 生成题，进行一轮可演练的模拟面试；支持语音提问。

**FR-04.1 两种出题来源**
| 模式 | 说明 |
|------|------|
| A. 整场模拟 | 从"面试记录"中选择任意一场，按其题目顺序（或打乱）逐一提问，用于复盘同场面试 |
| B. 简历 + 题库 | 导入简历（文本解析）→ 结合知识库题目随机抽取 + AI 依据简历/岗位生成新题（比例可调，如 6:4） |

**FR-04.2 简历导入**
- 支持格式：`.txt` / `.md`（零依赖）；`.docx`（本机已有 python-docx 可用）；PDF 视依赖情况（见 Q7）。
- 解析后抽取：技能栈关键词、项目名称、年限、岗位意向 → 用于生成针对性问题。
- 简历文本本地保存（`resumes` 表或 `data/resumes/`），不自动外传；AI 模式下仅发送必要片段。

**FR-04.3 面试流程与交互**
1. 选择模式 → 配置（题量 5/10/15、是否打乱、是否包含追问、出题配比、是否语音播报）。
2. 逐题展示：面试官提问（文本 + 可选语音）→ 我在输入框作答（或标记"不会"）。
3. 每题结束可选：查看参考要点（来自知识库该题优化建议/优秀作答）——**默认关闭，避免边看边答**。
4. 结束后生成"模拟报告"：逐题对照（我的回答 vs 知识库参考）、短板分类、下次建议、用时统计。
5. 会话入库：`mock_sessions`（配置、题序、时间）+ `mock_turns`（题目、我的作答、用时、评分/标记、来源：题库/整场/AI 生成）。

**FR-04.4 语音包（面试官 TTS）**
- 候选方案（开源/免费为主）：
  | 方案 | 特点 | 风险 |
  |------|------|------|
  | 浏览器 Web Speech API | 零依赖、离线可用（音色随系统） | 音色一般，受浏览器限制 |
  | edge-tts（Python 库） | 音色自然、体积小 | 需联网调用微软接口 |
  | Piper（本地神经 TTS） | 完全离线、音色较好 | 需下载模型（几十~几百 MB），当前环境无网络 |
  | ChatTTS / GPT-SoVITS | 音色最佳 | 依赖大、GPU 友好，个人本机偏重 |
- 推荐：**默认 Web Speech API（零依赖）+ 可选 Piper/edge-tts 作为增强**；实现为 `TTS Provider` 抽象，设置页可切换（与 LLM Provider 同构）。
- 无语音能力时自动降级为纯文本，不报错。

**FR-04.5 验收标准**
- [ ] 可选择任一面试记录发整场模拟，题目与原场一致且顺序可控。
- [ ] 可导入简历并成功解析出技能/项目关键词。
- [ ] 混合出题按配置配比生效，AI 生成题标注来源"AI 生成"。
- [ ] 作答过程可随时中断并保存进度；结束后产出结构化模拟报告。
- [ ] 语音播报可开关、可切换音色方案；无网络时自动降级不阻断。

## 6. 决策记录（已确认，含优化后的最终口径）

> 用户在 Phase 4 开工前确认"默认方案 + 同意计划"，并接受下列优化后的口径（原建议列见本节历史修订）。

| 编号 | 最终口径（已确认） | 优化点 |
|------|--------------------|--------|
| Q1 | 时长 = **整场面试时长（分钟，单字段）** | 输入容错：`58` / `58分钟` / `1h30m` / `1.5小时` 归一化为分钟；展示为"1 小时 30 分" |
| Q2 | 期望薪资 = **自由文本** | **不加结构化列**，仅展示层轻解析提示；避免冗余字段 |
| Q3 | 相似判定 = **规则层 + AI 灰区判定**，向量层暂缓 | 算法与阈值明确化（0.6×difflib + 0.4×2-gram Jaccard + 技术名词加权；相似 ≥0.72，灰区 0.55–0.72）；**入库时增量计算**并按类目分桶；AI 灰区**批量**判定且缓存结果 |
| Q4 | 对比页默认 3 列：来源/时间 + 忠实原文 + 优化建议 | 批注默认折叠；新增"仅看差异"开关；单条时退化为时间线 |
| Q5 | 反问环节采纳 `direction=reverse` 建模 | 判定收紧：**面试官邀请话术 + 我提问 + 面试官回答**三者同时满足才标 reverse；reverse 计入频次但不计入"回答质量"类统计；该栏建议语义为"提问准备" |
| Q6 | TTS 三档 Provider：`none / web（默认）/ edge` | piper 降为 P2；播放必须由用户手势触发；edge 音频缓存 `data/tts/`；纯文本始终可用 |
| Q7 | 简历支持 `.txt/.md/.docx` | docx 依赖缺失时给出"转存 txt"引导；解析出的技能/项目关键词**可人工编辑**；PDF 明确不支持 |
| Q8 | 设置存 `data/settings.json` | **原子写**（临时文件 + `os.replace`）；API Key 独立 `secrets.json`；**优先级反转：UI 设置 > `.env`**；`config` 改为可热生效（读取函数 + 缓存失效） |
| Q9 | 答案隐藏状态存浏览器本地 | 用 `<head>` 内联脚本注入 `html` class 实现**首屏即隐藏、无闪现**；不新增数据库字段 |
