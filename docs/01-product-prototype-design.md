## 0. 三条设计红线（贯穿所有阶段）

| # | 红线 | 本文档落实机制（详见 §4 / §5） |
|---|------|-------------------------------|
| R1 | 角色归属：问题来自面试官、回答来自我；有标签时保留说话人标签 | 有标签文本：标签优先建立映射，人工快速确认/纠错；无标签文本：AI 依据内容推断角色（v0.2 修订），推断结果带置信度、低置信段高亮，提供逐段/批量修正入口；所有 question/answer 均携带 speaker_id 且可随时纠错 |
| R2 | 答案忠实度：提取忠实原文（含口误卡壳），优化建议单独一栏，禁止提取=改写 | Question/Answer 只保存"忠实提取文本"+ 原文区间引用；提取文本默认只读；任何改写只能进入独立的"优化建议"字段；被人工改动的提取字段显式打标 `is_corrected` |
| R3 | 统一 schema，按知识点去重合并、统计频次，可跨次累积 | 全库统一数据模型；QAItem（单场事实）→ KnowledgeEntry（跨场面经）→ Category（知识点）三层结构；归一化键 norm 去重，ask_times 计数频次，保留出处引用 |

## 1. 产品定位

**一句话定位**：AI_Review 是一款面向求职者的个人 AI 面试复盘工具——把面试录音转写文本自动整理成"忠实原文的问答记录 + 独立优化建议 + 可跨场累积的面经库"，让每次面试都沉淀为下次面试的备战素材。

**目标用户**：
- 核心用户：正在求职/跳槽、希望系统化复盘面试表现的候选人本人（个人工具，单机使用）。
- 延伸用户（P2）：需要和朋友/同伴互做模拟面试并共享面经的小团队。

**核心价值（对应用户痛点）**：
1. **省时**：转写文本动辄上万字，手工切问答、归类极其耗时 → 自动切分问题/回答、归属说话人、初步打知识点标签。
2. **忠实且可改进**：先有"事实记录"（我当时到底怎么答的，一字不差），再有"改进方向"（我该怎么说更好），两者分开，不把复盘写成"美化后的回忆"。
3. **复利**：面经按知识点跨场去重合并、统计频次——哪类题总被问、哪类题答得欠佳，一目了然，库越用越值钱。

**边界（明确不做）**：不实现录音/音频导入与自动转写（v0.2 修订，只消费已有的转写文本）；不做简历解析；不做岗位投递管理；不做多端账号体系（P0/P1 均为本地单机）。

## 3. 用户流程图

### 3.1 主流程（文字 + 编号步骤）

1. **新建复盘**：从工作台点"新建复盘"，或从历史列表继续进行中的复盘。
2. **补元信息**：填公司、岗位、面试类型（技术/行为/HR/综合/模拟）、日期（默认今天）。
3. **导入文本**：粘贴转写文本或上传 `.txt`/`.md`；系统自动识别说话人标签。
4. **说话人识别与角色确认（R1 闸门）**：
   - 有标签：直接列出"说话人 → 角色（面试官/我）"映射供人工确认/纠错，通常一次点击完成；
   - 无标签：**AI 依据内容推断角色**并高亮低置信片段，用户可逐段或批量修正；
   - 角色映射异常（标签混乱/推断明显错误）：进入修正界面，改完再解析。
5. **AI 解析**：按轮次切分 → 提取问题与回答 → 初判知识点 → 低置信条目打 **[待确认]**。
6. **人工校对（问答列表）**：逐条确认切分与归属；支持合并（追问连答）、拆分、改角色归属、改知识点/标签、删除误识别条目。
7. **单题复盘**：核对"忠实原文提取"（点击原文引用跳转高亮），在独立"优化建议"栏填写/采纳改进方向，为本题写批注（当时的感受、要点补充等）。
8. **纳入面经库**：对已确认题目一键入库（或整场批量）：按知识点去重合并——已存在 → 频次 +1、变体问法并入、出处追加；不存在 → 新建知识点与面经条目。
9. **沉淀与回看**：浏览面经库（跨场聚合卡片）、查看统计。
10. **导出**：选择范围（本场复盘 / 面经库快照）、勾选内容、生成下载 Markdown。

### 3.3 异常路径预案

- **双面试官/多人**：允许多个 interviewer/other 角色，问题归属具体说话人 ID。
- **无关说话人/杂音轮次**：可折叠不参与提取。
- **无标签文本推断错误**：低置信高亮 + 批量修正；单段角色可改后重新局部解析。
- **重复导入**：按内容哈希提示"疑似重复导入"，可选跳过。
- **对解析结果存疑**：单题复盘点"原文引用"直接核对原始转写。

## 5. 数据模型设计

### 5.1 设计原则
1. **统一 schema**：所有面试数据同构，跨场累积才有意义（R3）。
2. **两层粒度**：`QAItem`（事实层，记录"这一场怎么问怎么答"，语义不可篡改）；`KnowledgeEntry`（聚合层，跨场沉淀的面经，可被持续优化）。
3. **提取与建议分离（R2）**：忠实提取字段（extract_text / corrected_text）与优化字段（optimization）分属不同字段，任何流程不得混写。
4. **可溯源（R2/R3）**：每个提取文本带 `source_ref`（原文字符区间 + 片段引用）；面经条目标记所有出处场次。
5. **机器结果可审计**：AI 产出记录置信度与解析器版本；人工改动显式打标，不静默覆盖。

### 5.2 实体关系总览（ASCII）

```
InterviewRecord 面试记录
   │ 1
   ├─── n Speaker         说话人(角色映射: 谁=面试官/我)
   ├─── n QAItem          问答条目(本场事实) ──1:1── Question(问题,内嵌)
   │         │ 1                       └─1:n── Answer(回答,内嵌)[] + annotation(批注)
   │         │ n
   │         ▼
   │     n─1 KnowledgeEntry 面经条目(跨场聚合) n─1 Category 知识点
   │         │                                  │(parent_id 二级树)
   │         └──n:1  InterviewRecord(经 source refs 追溯出处)
   QAItem n─n Tag ； KnowledgeEntry n─n Tag ； Category 1─n Category(子类)
```

- 单场事实链：`InterviewRecord → QAItem → {Question, Answer[], 批注}`
- 跨场沉淀链：`QAItem → KnowledgeEntry → Category`
- 两条链通过 `QAItem.entry_id` 桥接；聚合层永不删除事实层数据。

### 5.3 实体定义（字段级）

#### ① InterviewRecord 面试记录
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID | ✔ | 主键 |
| title | string | ✔ | 标题，默认「公司-岗位-YYYY-MM-DD」，可改 |
| company / position | string | – | 公司 / 岗位（可选） |
| interview_type | enum | ✔ | technical / behavior / hr / mixed / mock |
| date | date | ✔ | 面试日期 |
| raw_transcript | text | ✔ | 导入的原始转写全文（只读存档，永不被改写） |
| transcript_format | enum | ✔ | 标签格式：bracket / colon / ab_speaker / timecode / none |
| speaker_map | Speaker[] | ✔ | 说话人→角色映射（有标签=标签直读+确认；无标签=AI 推断+可修正） |
| status | enum | ✔ | draft / parsing / review / done / archived |
| parser_version | string | – | 解析器版本（审计用） |
| created_at / updated_at | datetime | ✔ | 时间戳 |

#### ② Speaker 说话人（内嵌于 InterviewRecord）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 如 sp_interviewer / sp_self / sp_other_1 |
| label | string | 原始标签（如「面试官」「我」「A」）；无标签文本为系统生成的占位名（如"说话人1"） |
| role | enum | interviewer / self / other / unknown（unknown 需人工处理后才能进入提取） |
| source | enum | label（来自标签）/ inferred（AI 依内容推断，v0.2） |
| confidence | float 0–1 | 推断置信度（source=inferred 时有效，低置信段供高亮） |
| color | string | 界面配色标识 |

#### ③ QAItem 问答条目（本场事实粒度）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| interview_id | UUID | 所属面试记录 |
| seq | int | 本场提问顺序（决定列表与导出顺序） |
| parent_id | UUID | 可空；追问链指向上一问 |
| status | enum | auto(机器初提) / pending(待确认) / confirmed / corrected |
| question | Question | 内嵌问题对象 |
| answers | Answer[] | 内嵌回答对象数组 |
| category_id | UUID | 知识点归属 |
| entry_id | UUID | 可空；纳入面经库后指向 KnowledgeEntry |
| annotation | text | **批注**（v0.2：简化的自评表达——对本题的感受/要点补充/待办，自由文本） |
| tag_ids | UUID[] | 标签 |
| confidence | float 0–1 | 提取整体置信度，低于阈值自动置 pending |
| created_at / updated_at | datetime | 时间戳 |

#### ④ Question 问题（内嵌于 QAItem）
| 字段 | 类型 | 说明 |
|------|------|------|
| text | string | **忠实提取的问题文本**（只读语义；出错经修正流程） |
| source_ref | SourceRef | 原文区间引用（start_char / end_char / quote），可跳转核对 |
| speaker_id | string | 提问者，默认 interviewer（R1；可纠错） |
| confidence | float 0–1 | 切分置信度 |
| is_corrected | bool | 是否被人工修正过 |

#### ⑤ Answer 回答（内嵌于 QAItem）★ R2 核心载体
| 字段 | 类型 | 说明 |
|------|------|------|
| extract_text | string | **机器从原文忠实提取的回答文本**：保留口误、卡壳、语气词，与 source_ref 引用内容一致；界面只读 |
| corrected_text | string | 可空；仅当用户判定提取有误时填修正副本，原提取与引用保留可对比 |
| is_corrected | bool | 是否有修正（有则显示「已修正」徽标） |
| source_ref | SourceRef | 原文区间引用 |
| speaker_id | string | 回答者，默认 self（R1） |
| duration_sec | int | 发言时长（文本时间戳可估算时） |
| fidelity_check | enum | pass / warn（P1：自动比对 extract_text 与引用文本一致性） |

> R2 的机器保证：**"提取/修正"字段 ≠ "优化建议/批注"字段**。优化建议只存于面经条目 optimization 与单题复盘编辑框；批注只存于 QAItem.annotation——任何 UI 都不提供"修改 extract_text 以润色"的入口。

#### ⑥ Category 知识点/类别（树状，一级下可挂子类）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | string | 显示名，如「JVM内存模型」 |
| norm | string | **归一化去重键**（小写+去空白/符号）；同 norm 视为同一知识点（R3） |
| parent_id | UUID | 可空；二级树 |
| type | enum | technical / behavior / hr / other |
| created_at / last_asked_at | datetime | 创建时间 / 最近被问时间 |

#### ⑦ KnowledgeEntry 面经条目（跨场聚合粒度）★ R2/R3 核心载体
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| category_id | UUID | 主归属知识点 |
| head_question | string | 代表问法（通常取最近/最典型一场的问题文本） |
| question_variants | string[] | 变体问法（跨场累积） |
| core_extract | text | **核心忠实答案提取**（聚合展示，默认取最近一场的忠实文本；仍与 optimization 分栏） |
| optimization | text | **优化建议（独立字段）**——聚合层面的改进方向沉淀 |
| source_qa_ids | UUID[] | 出处：覆盖的 QAItem 列表（R3 跨场追溯） |
| ask_times | int | 频次 = 关联 QAItem 数（R3） |
| tag_ids | UUID[] | 标签 |
| first_asked_at / last_asked_at | datetime | 首问 / 最近问时间 |
| updated_at | datetime | 最后合并更新时间 |

#### ⑧ Tag 标签（QAItem 与 KnowledgeEntry 共用）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | string | 标签名（如 Redis、STAR、压力面） |
| color | string | 展示色 |

#### SourceRef 原文引用（Question / Answer 共用值对象）
| 字段 | 类型 | 说明 |
|------|------|------|
| start_char / end_char | int | 在 raw_transcript 中的字符区间 |
| quote | string | 区间原文片段（校验与高亮用） |

### 5.4 端到端示例（展示"提取/建议/批注"分离）
```
raw_transcript 片段(无标签场景示意):
  你好，欢迎参加面试，先做个自我介绍吧。
  好的，我叫XXX…嗯…之前在YY做后端，主要负责…
  你提到用了本地缓存，能具体讲讲实现吗？
  嗯…当时我们用…呃…其实先查数据库，后来发现慢了才加的缓存…

Speaker(source=inferred): {说话人1→interviewer(0.95)}, {说话人2→self(0.93)}

QAItem #3:
  question:  { text: "你提到用了本地缓存，能具体讲讲实现吗？",
              source_ref: {区间…}, speaker_id: sp_interviewer, confidence: 0.94 }
  answers:   [ { extract_text: "嗯…当时我们用…呃…其实先查数据库，后来发现慢了才加的缓存…",
                 corrected_text: null, is_corrected: false,
                 source_ref: {区间…}, speaker_id: sp_self } ]
  category_id: cat_cache
  annotation: "开头卡壳了，下次先给结论；记得补充缓存击穿的例子"     // 批注(v0.2)

面经库合并后 KnowledgeEntry (命中 cat_cache 既有条目):
  head_question: "本地缓存实现", question_variants: […],
  core_extract: "<最近一次确认的忠实原文>",   // 独立字段A
  optimization: "先给结论；讲触发时机/淘汰策略；补缓存击穿案例",  // 独立字段B
  source_qa_ids: […], ask_times: 5, last_asked_at: 2024-05-20
```

### 5.5 去重 / 合并 / 频次规则（R3）
1. **入库触发**：QAItem 状态为 confirmed/corrected 后，由用户"纳入面经库"（单题或整场批量）触发。
2. **找知识点**：归一化问题文本查同场/跨场条目——命中 KnowledgeEntry → `ask_times + 1`、变体去重并入、`source_qa_ids` 追加、更新 `last_asked_at`；未命中 → 按 `norm` 查/建 Category，再建 KnowledgeEntry。
3. **norm 冲突**：同名不同语义（一词多义）时，人工在合并确认弹层选择"归入现有 / 另立新类 / 改名"。
4. **频次口径**：条目频次 = 关联 QAItem 数；类别频次 = Σ 子条目；统计页与排序均以此为准。
5. **删除语义**：QAItem 仅软删除，并从所属 KnowledgeEntry 的 `source_qa_ids` 摘除、频次减一；raw_transcript 永不删除。
6. **跨场累积可视**：面经库卡片"出处 N 场" = `source_qa_ids` 归属场次去重计数；展开可见各场批注。

### 5.6 红线 → 字段/机制映射表

| 红线 | 数据层落实 |
|------|-----------|
| R1 角色归属可溯、不静默错配 | `Speaker.role + source(label/inferred) + confidence`；有标签保留标签；无标签推断结果低置信高亮且全部可改；`Question.speaker_id`/`Answer.speaker_id` 携带来源，支持纠错 |
| R2 提取≠改写 | `Answer.extract_text`（只读）+ `corrected_text`（显式修正标记）+ `source_ref` 可核对；优化建议只存于 `KnowledgeEntry.optimization` 与复盘编辑框；批注只存于 `QAItem.annotation` |
| R3 统一 schema、去重、频次 | 唯一 schema 全库共享；`Category.norm` + `KnowledgeEntry` 聚合去重；`ask_times` 频次；`source_qa_ids` 跨场出处追溯 |
