## 2. 关键实现

### 2.1 专题与分类规则（`app/knowledge.py`）
- 专题优先级：**反问（direction=reverse）→ 自我介绍 → 个人发展**（职业规划/优缺点/离职/求职动机/薪资/成长等）。
- 一级分类优先级：**系统设计 → 技术栈 → 项目经历 → 团队协作 → 行为问题 → 其他**。
  顺序经过实测修正：最初把"项目/行为"关键词排在技术栈之前，导致"项目里用的缓存怎么实现"被误归到"项目经历"；现在**技术栈优先**（`category_type=technical` 或命中技术词表）。
- 分类结果落 `entries.topic` / `entries.group_name`；知识库页对历史数据做**懒补分类**，另提供「重跑分类」按钮全量重算。

### 2.2 相似度打分（`app/pipeline/similar.py`）
初版只用"difflib 序列相似 + 2-gram Jaccard"，实测中文改写几乎无法命中（同义问法仅 0.44）。现改为四层加权：

```
score = 0.25 × 字符集合 Jaccard
      + 0.25 × 中文 2-gram Jaccard
      + 0.20 × difflib 序列相似度
      + 0.30 × （领域词 + 规范化意图词）Jaccard
      + 共同技术名词加权（≤0.08）
```

- **意图词规范化**：`讲讲/说说/谈谈 ≈ 介绍`、`怎么实现/实现原理 ≈ 实现`、`怎么处理/如何保证 ≈ 处理`、`怎么优化 ≈ 优化`、`为什么 ≈ 原因`。
- 阈值：**≥0.72 自动判相似**；**0.45–0.72 记为"疑似"**（非 AI 模式也能看到线索，人工一键确认/取消）；<0.45 忽略。
- 计算时机：**入库后增量重算**，按一级分类分桶（每桶上限 80，超限按频次取前 N），避免全库两两比较。
- AI 模式：把灰区候选**批量**（8 对/次）交 LLM 判定；判定为同一问题 → 升级为 `method=ai`；判定为不同 → **撤销**规则层的"疑似"记录。
- 优先级：`manual > ai > rule`，低优先级永不覆盖高优先级。

### 2.3 对照页（`compare.html`）
- 左：相似条目清单（分数 + 判定来源 + 确认为同一问题 / 取消关联）。
- 下：历史作答对比表（来源面试与时间、忠实原文逐字引用、优化建议、批注 + 标为最佳作答）。
- 手动关联：输入问题文本 → 相似候选检索（`/api/knowledge/search`）→ 一键关联（`method=manual`）。
- 红线保持：对比表里"回答"永远是忠实原文（含口误卡壳），优化建议/批注独立成列。

### 2.4 反问环节的工程细节
- `qa_items.direction` 在 Phase 4 已建列，但**插入时未写库**（默认 normal）——本阶段修复 `insert_qa` 的列清单后反问才能正确留存；
- 邀请话术本身**不单独成题**（仅在全程没有提问时才作为待确认条目保留），避免产生"面试官问'你有什么想问的'但无回答"的噪音条目。

## 4. 验证结果（本阶段新增断言）

- 反问条目：`direction=reverse`、待确认、邀请话术不单独成题 → 通过；
- 专题：`自我介绍 → self_intro`、`反问 → 反问环节` 专题；每个条目都有 `group_name` → 通过；
- 相似：两场近似问法自动关联（规则层 ≥0.72 落库、可查询分数与方法）→ 通过；取消关联后计数减少 → 通过；
- 对比页：渲染"相似问题关联 / 历史作答对比 / 优化建议"；数据可回溯到具体面试与作答；标为最佳作答持久化 → 通过。

## 5. 已知边界

- AI 灰区判定需配置 Key（无 Key 时灰区以"疑似"呈现，仍可人工确认）；
- 相似对列表未做分页（个人量级足够）；
- 反问条目计入频次，但不参与"回答质量"类统计（符合 SRS Q5 口径）。
