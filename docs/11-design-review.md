## 2. 四维度逐项评审

### 维度一：易用性与信息架构 —— **3.5 / 5**

**结论**：主干流程清晰（导入→复盘→知识库→模拟），导航项与用户心智一致；但**异步状态反馈与"离开即丢数据"风险**、导入向导的一次冗余步骤拉低了分数。

**证据 / 亮点**
- 顶栏 5 项导航与 13 个页面职责一一对应，二级页面均有 `.crumbs` 返回路径（`base.html` + 各模板）。
- 记录页提供搜索 + 快筛（待确认/未入库）+ 4 种排序（`index.html`），空态文案齐全（全站 11 处空态）。
- 「全部隐藏答案 / 复习模式」+ 首屏内联脚本注入（`base.html`、`review_list.html`）实现**无闪烁的复习态**，是真实体验加分项。
- 导入重复检测用 409 + 前端二次确认，避免误重复入库（`import.html`）。
- 单题复盘双栏（左忠实原文只读 / 右优化建议+批注），与"提取≠改写"的心智一致（`review_detail.html`）。

**问题清单**
| 级别 | 问题 | 位置 | 证据 | 改进建议 |
|------|------|------|------|----------|
| 阻塞 | **作答/批注未保存即离开会丢数据**：模拟作答与单题复盘只有显式"保存"才落库 | `mock_run.html` L149-162、`review_detail.html` 保存按钮 | 全仓 grep `beforeunload|autosave|visibilitychange` = **0 命中**；`save()` 仅由按钮与 Ctrl+Enter 触发 | ① 输入 800ms 防抖自动保存；② `beforeunload` 脏数据提示；③ 保存成功后显示"已保存 · 时间"微字 |
| 重要 | 导入向导存在**一次无收益步骤**：必须点「识别说话人与格式」才出现角色确认与创建按钮 | `import.html` | 面板 `#analyze-result` 默认 `display:none`，未识别前无法创建 | 文本变化 500ms 后自动 analyze；或提供"跳过识别，直接创建（默认按标签直读）" |
| 重要 | 长任务无进度/可取消：相似重算（AI 模式会串行调用 LLM）、整场入库、模拟出题只有按钮禁用 + 文案 | `knowledge.html` 重算按钮、`review_list.html` 整场入库、`mock_setup.html` 开始模拟 | 8 处"…中"文案，无 spinner/进度条（`animation` 统计 = 0） | 按钮内联 spinner + 顶部 indeterminate 进度条；重算改为后台任务 + 轮询/SSE |
| 重要 | 无分页/虚拟滚动，记录页与知识库全量渲染 | `index.html`、`knowledge.html` | 列表接口无 limit/offset（`repository.list_interviews` 全量） | 每页 20 条 + "加载更多"；或前端虚拟列表 |
| 建议 | 移动端导航为横向滚动条（非汉堡/底部 Tab） | `style.css` `@media(max-width:640px)` 中 `nav{overflow-x:auto}` | 5 项导航在 390px 宽下需滑动 | 折叠为"更多"菜单或底部 Tab（HIG/Material 惯例） |
| 建议 | 错误提示混用页面横幅与原生 alert | 全站 26 处错误处理 | `alert()` 用于 API 错误、原生 `confirm()` 用于破坏性操作 | 统一为 Toast + 确认弹层（见维度四） |

### 维度二：功能价值与页面唯一性 —— **4.0 / 5**

**结论**：功能点与需求一一对应，**没有"为功能而功能"的堆砌**；主要冗余集中在"导出"入口重复与旧路由命名，以及"单题工作被拆成两个页面"。

**证据 / 亮点**
- 每个功能可追溯到 SRS 条款并在 UI 有落点：答案隐藏=FR-02、三专题/相似/对比=FR-03、模拟三模式=FR-04、主题/模型/模式=FR-05。
- 高价值差异化设计：① 忠实原文只读 + 原文区间引用（`review_detail.html`）；② 知识库"同一考点多次作答并列对比"替代重复条目堆积（`compare.html`）；③ 模拟面试直接复用知识库（非另起题库）；④ 反问环节 `direction=reverse` 独立建模。
- "删除后影响"评估：任一页面删除都会造成明显功能缺口（对比页删除 → 相似关联失去落点；模拟删除 → 演练闭环消失），说明页面职责基本唯一。

**问题清单**
| 级别 | 问题 | 位置 | 证据 | 改进建议 |
|------|------|------|------|----------|
| 重要 | **导出入口与预览页重复**：同一产物有"预览页 + 直接下载"两条路径，且分散在 3 个页面 | `/interviews/<id>/export`、`/bank/export`、`index.html`、`review_list.html`、`knowledge.html` | 5 处导出入口；预览页仅把 Markdown 贴进 `<pre>`，而下载按钮就在同页 | 收敛为"下载 + 可选预览抽屉（Drawer）"；删除独立预览页，或将其变成"导出历史（data/export 文件列表）" |
| 重要 | **路由命名与页面名不一致**：页面叫"知识库"，路径仍是 `/bank`、`/bank/export` | `main.py` `page_bank`（302）、`page_export_bank` | 旧路径保留导致"跳转目标与预期不符"的隐患（分享/书签语义混淆） | 全部迁移到 `/knowledge*`，`/bank*` 只保留 301 并在页脚注明；同步修正模板内链 |
| 重要 | 单题工作被切在两个页面：**隐藏答案只在列表页、标记修正只在详情页** | `review_list.html` vs `review_detail.html` | 列表页无编辑入口，详情页无隐藏开关 | 列表页行内展开"快速编辑"（批注/建议/修正）；或详情页加"隐藏答案"按钮 |
| 建议 | 记录卡片次要信息偏多（题数/待确认/无回答/已入库/解析器） | `index.html` `.rec-counts` | 单卡片 5 类计数 + 3 个 chip + 3 个操作 | 保留"待确认/无回答"两类警示计数，其余折叠进详情 |
| 建议 | 操作文案部分偏工程化："重跑分类""整场入库""无回答" | `knowledge.html`、`review_list.html` | 用户视角更常见的说法是"重新归类""全部加入知识库""未提取到回答" | 统一面向用户的措辞表 |

### 维度三：视觉设计与动效 —— **3.5 / 5**

**结论**：**视觉系统扎实、克制且一致**（token 化彻底、对比度优于标准、桌面留白专业），但**几乎零动效与零骨架屏**，异步过程"只有文字没有动静"；组件密度在个别页面偏高。

**证据（可量化）**
- 配色：`style.css` 中 **token 块之外仅 1 处硬编码色**（`#fff`，用于主按钮文字），其余全部走变量 → 规范度高。
- 对比度（像素实测）：浅色 **6.2:1**、深色 **10.2–10.9:1**（WCAG AA 正文要求 4.5:1）→ 超标。
- 布局：1440px 下容器左右留白 **186 / 189px**（`max-width:1100px` 生效），30 张截图**无横向溢出、无内容截断**。
- 圆角 4 档（6/8/12/999px）、间距 8px 基准、阴影 2 档、字体 1 套系统栈 → 一致性良好。
- 亮/暗主题双向覆盖：`[data-theme="dark"]` 覆盖 30 个变量，浅/深两套各 10 页全部审计通过。

**问题清单**
| 级别 | 问题 | 位置 | 证据 | 改进建议 |
|------|------|------|------|----------|
| 重要 | **零动效、无过渡**：页面切换、卡片出现、折叠菜单展开均为硬切 | 全站 | `@keyframes` = 0；`animation` = 0；`transition` 仅 3 处 | 加 3 类克制动效：卡片入场 `opacity/translateY 120ms`、popover `scale 100ms`、进度条 `width 200ms`；并支持 `prefers-reduced-motion` |
| 重要 | 异步无加载形态：解析/入库/出题/测试连接只有文字"…中" | `import.html`、`knowledge.html`、`mock_setup.html`、`settings.html` | 加载文案 8 处，无 spinner/skeleton/progress 元素 | 引入 `<div class="spinner">` 与骨架卡片（AntD Skeleton 心智）；按钮内联 loading 态 |
| 建议 | 破坏性操作视觉权重不足：删除按钮与普通按钮仅靠颜色区分，且触发原生对话框 | `review_list.html` 更多校对 | `.btn.danger` 仅改文字色/边色 | 危险操作加图标 + 二次确认弹层 + 撤销 Toast |
| 建议 | 信息密度局部偏高：本场复盘页 **25 个按钮**、知识库卡片 3 列双栏 | `review_list.html`（7 卡片/25 按钮）、`knowledge.html` | design_audit 计数 | 行内操作默认 3 个（隐藏答案/复盘/入库），其余收进"更多"（已部分实施）；知识库卡片改为单列两段式 |
| 主观偏好（立场：效率优先） | 无图标体系，全文字按钮 | 全站 `.btn` | 0 个图标；按钮文案 2–5 字 | 可为"下载/隐藏/删除/播放"配线性图标，但保留文字标签；纯文字也可接受，属审美取舍 |

### 维度四：设计规范与借鉴 —— **3.0 / 5**

**结论**：**视觉规范遵循度高**（token/对比度/响应式/深色），但**组件层与无障碍层与主流规范差距明显**：无 ARIA、无统一弹层/Toast/Skeleton 组件，破坏性操作用浏览器原生对话框。

**证据（可量化）**
- `aria-*` / `role=` 使用：**0 处**（13 个模板全量 grep）；`alt`：0（无图片，属正常）。
- `<label>` 32 个 vs `<input|select|textarea>` 41 个：多数通过外层 `<label>` 包裹合规，但进度条、分隔区域、动态状态均无语义标注。
- 原生 `confirm()/alert()/prompt()`：**23 处**（含"删除问答""取消关联""清除 Key""拆分输入"）。
- 键盘：仅 1 处快捷键（模拟作答 `Ctrl/⌘+Enter`）。
- 断点：3 个（640 / 700 / 900px），符合 Mobile-first 的简化实现。

**符合与不符合主流规范的对照**
| 规范惯例（Ant Design / Material / HIG） | 本项目 | 判断 |
|---|---|---|
| Token 化设计系统（色/间距/圆角/阴影） | ✅ 21+30 变量、4 档圆角、8px 基准 | 符合 |
| 深浅色主题 + 跟随系统 | ✅ `data-theme` + `prefers-color-scheme` | 符合 |
| 破坏性操作用模态确认（Modal.confirm） | ❌ 原生 `confirm()` | 不符合 |
| 操作反馈用 Toast（而非阻塞 alert） | ❌ 页面横幅 + `alert()` | 部分不符合 |
| 异步加载用 Skeleton/Spin | ❌ 纯文字 | 不符合 |
| 空态用插图 + 主行动（Empty 组件） | ✅ 文案 + 主按钮（11 处） | 符合（无插图，可接受） |
| 表单校验即时反馈（Form item validate） | ✅ 时长/薪资提示（`import.html`） | 符合 |
| 可访问性（ARIA、焦点管理、键盘可达） | ❌ 0 ARIA、焦点样式仅 4 条 | 不符合 |
| 列表分页/虚拟滚动 | ❌ 全量渲染 | 不符合 |
| 危险操作可撤销（Undo Snackbar） | ❌ 软删除但无撤销入口 | 不符合 |

**可借鉴的成熟模式（落地清单）**
1. **Ant Design**：`Modal.confirm` + `message.success/error`（Toast）替换 23 处原生对话框；`Skeleton` 用于导入解析与相似重算。
2. **Material Design 3**：`Filled Tonal Button` 语义（主/次/危险三级已具雏形，建议加 tonal 次级）+ `Snackbar` 撤销。
3. **Apple HIG**：长列表用分页/渐进加载；底部 Tab 替代移动端横向滚动导航；破坏性操作二次确认 + 明确后果文案。
4. **Notion/Linear 类工具**：`⌘K` 全局搜索（跳页面/题目/知识点），本项目已具备数据基础（`/api/knowledge/search`）。

**本项目亮点（值得保留）**
- 三红线在 UI 层可见且不可绕过：忠实原文只读 + 原文区间 + 独立优化建议栏；
- 相似识别给出"判定来源与分数"（规则/AI/人工），**可解释的智能**比黑盒更有信任感；
- 复习模式首屏无闪烁（内联脚本注入 class）——细节工程做得比多数原型更扎实；
- 自带像素审计脚本，把"美观"变成可回归的指标（对比度/留白/溢出）。

## 4. 优先级排序的可落地改进清单

### P0（1–2 天，直接消除体验风险）
1. **自动保存 + 离开保护**（`mock_run.html`、`review_detail.html`）：输入 800ms 防抖 `POST`；`beforeunload` 提示；保存态微文案"已保存 12:03"。

### P1（3–5 天，结构化提升）
4. **无障碍补齐**：`role="progressbar"`（`.progress`）、`aria-live="polite"`（flash/toast 容器）、`fieldset/legend`（设置页主题与模式单选）、`aria-expanded`（"更多校对"改为 button 控制）、`:focus-visible` 覆盖 chip/链接/导航、弹层焦点陷阱。目标：0 → 30+ ARIA 标注。
