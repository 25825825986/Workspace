## 0. 先说清楚我对这个产品的理解（若不符请纠正）

| 项 | 我的判断 | 依据 |
|---|---|---|
| 产品 | AI_Review —— 面试复盘与考点积累工具 | README / 13 个页面路由 |
| 用户 | **一个人**：正在求职、要连续面多轮的工程师本人 | 单机、`data/` 本地落盘、无登录、无多租户 |
| 主要任务 | 把一场面试的**转写稿**变成 ①可逐字核对的问答 ②独立成栏的复盘建议 ③跨场累积的考点账 ④可演练的模拟面试 ⑤导出 Markdown | `service.py` 编排、三条设计红线 |

**结论**：这是一个**工作台**，不是仪表盘，更不是营销页。设计目标不是"看起来专业"，而是"让人愿意把一份长稿读完、并且越用越厚"。

## 1. 现状诊断

### 1.1 一句话结论

**功能骨架和工程一致性都很好（Phase 8 之后已无明显可用性缺陷），但这套界面没有自己的视觉身份——遮住导航文字后，认不出哪一页是逐字稿、哪一页是知识库。**

### 1.2 三个结构性问题（不是审美偏好，是可验证的缺陷）

**① 最严重：产品红线「提取 ≠ 改写」在视觉上没有执行。**

单题复盘页左栏的「忠实原文」和右栏的「优化建议」是**同一个面**——同底色、同边框、同圆角、同字号。

> 实测（`04_single_qa.png`）：两栏的面都是 `#FFFFFF`，边框都是 `#D5DBE6`，字号都在 13–14px 一档。

也就是说，界面上**分不出哪一块是证据、哪一块是 AI/自己的加工**。而"建议永不覆盖原文"是这个产品写在文档里的第一条红线。红线只存在于文案里，没有变成版式事实。

**② 颜色不传递任何信息。**

全站唯一强调色 `#2563EB` 同时兼任**四个互不相干的角色**：主按钮、次按钮、导航当前项、模型徽标文字。而真正有语义的状态色（未提取到回答 = `#B45309`）只有 11–12px，是全页最容易被漏掉的信息——**唯一需要用户动手的那条，恰恰最看不见**。

**③ 层级的字阶是假的，容器层级是塌的。**

- 正文 13–14px 与标签 11–12px 只差 1–2px，实际可感知层级只有 3 档；
- 首屏最大的字号预算给了 4 个 KPI 数字（28–30px），而当前数据下其中 2 个是 `0` 或重复值；
- KPI 卡、记录卡、题目卡、答案块、批注输入框**全部同半径、同边框、同底色、同阴影**，只有宽高不同；同一屏出现 4 层容器嵌套，把本该连续阅读的逐字稿切成碎片。

### 1.3 五类"模板化痕迹"（按 skill 的通用默认清单逐条核对）

| # | 痕迹 | 本项目中的具体位置 |
|---|---|---|
| 1 | 同样的圆角卡片 + 统一柔和阴影 | `.card` / `.rec-card` / `.qa-row` / `.entry` / `.stat` 全部 `--r-lg` + 同一 `--shadow` |
| 2 | 元信息用 `·` 连接 | 页脚「AI_Review · v0.5.0 · 本地运行 · 数据保存在项目 data/ 目录」、徽标「AI 模式 · deepseek-ai/…」、记录卡元信息行 |
| 3 | 链接/按钮尾部加 `→` | 「创建并解析 →」「查看对比 →」「查看知识库该考点…→」「知识库对比 →」 |
| 4 | 装饰性编号 | 设置页 `① 主题外观 / ② AI 模式 / ③ 模型 API`——这只是分组，**不是流程** |
| 5 | 每个区块入场都 fade + slide-up | `.card,.rec-card,.qa-row,.entry{animation:ui-rise}` —— 每张卡片都播一次 |

### 1.4 被埋没的三个真正差异点（现状 vs 应有的视觉重量）

| 差异点 | 现状 | 问题 |
|---|---|---|
| 原文区间溯源（`[字符区间 6-28]`） | 12px 灰字，塞在引文块尾部 | 这是"可溯源"的唯一凭据，却是最弱的字 |
| 被问频次 `ask_times` | 12px 灰字 | 这是知识库的核心资产，肉眼无法比较大小 |
| 未提取到回答 | 12px 赭色，在卡片第三行 | 唯一需要用户动作的状态，最难发现 |

## 2. 设计方案：**边注本（Margin Notes）**

### 2.1 核心主张

> **把"页码边的批注"这个动作做成版式本身。**
>
> 原文永远是房间里最亮的东西；批注在物理上不可能盖住原文。

这不是风格选择——它是把产品第一条红线从文案变成用户不需要读说明就能感知的**物理事实**：

```
现在：  原文 = 白面+灰边+圆角+13px        →  改成了 ：
        建议 = 白面+灰边+圆角+13px            原文 = 纯白面（全站唯一）+ 直角 + 宋体 15.5px/1.9 + 行长 36em
        （肉眼无法区分）                       建议 = 内凹灰面 + 无衬线 13px + 位于主栏之外的窄栏
```

第二条主张：**把颜色从"装饰"里解放出来，让它只承担状态。**

### 2.2 Token 系统

#### 颜色（6 个命名值）

| Token | 值 | 唯一用途 |
|---|---|---|
| `--paper` | `#FFFFFF` | **原文/证据面**。全站最亮的面，只给"必须逐字读"的内容 |
| `--desk` | `#EDF0F3` | 页面底（工作台）。比现在 `#F5F7FA` 深一档，让纸面真的浮起来 |
| `--margin` | `#E4E8EC` | **批注栏面**（内凹，比工作台更深，明确"这不是正文"） |
| `--ink` | `#16191D` | 原文墨 / **主操作按钮填充** |
| `--ink-2` | `#4C545C` | 界面文字、标签 |
| `--muted` | `#6E7780` | 附注（白底 4.6:1，过 AA） |
| `--seal` | `#2C6A55` | **状态色 A（唯一）**：已确认 / 已入库 / 最佳作答 —— 用户自己拍板的事 |
| `--flag` | `#A2561C` | **状态色 B（唯一）**：缺口 —— 未提取到回答 / 待确认 |

**关键决策：主操作改用墨黑填充，不再用彩色。**

理由：现在一个蓝同时干四件事，等于颜色不传递信息。把动作收进墨黑之后，**全站彩色只剩下两个语义**——"你确认过的"（松绿）和"你还没处理的"（赭）。颜色从此可以一眼读。

> 已核算对比度：`--seal` 白底 6.36:1、`--flag` 白底 5.40:1、`--muted` 白底 4.60:1，均 ≥ AA 4.5:1。

#### 字体（两族 + 一个数字特性）

| 角色 | 字体 | 规格 |
|---|---|---|
| **原文 / 逐字稿** | 思源宋体 `Noto Serif SC`，回退 `Source Han Serif SC, Songti SC, STSong, SimSun, serif` | 15.5px / 行高 **1.9** / 行长 **≤36 个全角字** |
| **界面 / 批注** | 思源黑体 `Noto Sans SC`，回退 `PingFang SC, Microsoft YaHei, sans-serif` | 14px / 行高 1.7（视觉标签 13px） |
| **数字对齐** | 不引入等宽字体，用 `font-variant-numeric: tabular-nums` | 仅用于时间、字符区间、频次 |

**为什么用宋体做原文**：在中文语境里，宋体 = 被引用的、原始的、有权威的文本（书、公文、引文）；黑体 = 系统在说话。一次字体切换就把"原文"和"我的加工"分开，比任何彩色标签都省，且不需要教育用户。

**自我修正（重要）**：初稿曾打算引入 JetBrains Mono 做"小数据标签"。**已放弃**——"给小号数据标签配等宽字体"本身就是模板化的典型特征之一。这里真正需要的只是**对齐**，`tabular-nums` 足够。等宽只保留给本来就该等宽的 `<code>` / 模型 ID / 原文区间。

#### 版式

```
页宽：阅读类页面主栏收窄到 640–680px（≈36 全角字），不再是通栏 1067px
双栏：主栏 1.6fr │ 批注栏 1fr，之间是 1px 明度接缝，不是两张圆角卡片
对齐：一律左对齐；批注栏顶部对齐到它所属段落的基线
留白：语义分档，取代现在"全部 16–24px"的均质节奏
      段内 8 · 条目间 16 · 区块间 40 · 页面区段间 64
形态：面是直角，控件是圆角（8–10px）
      —— 圆角只属于「可点的东西」，纸面永远直角
```

### 2.3 三条设计原则

1. **房间里最亮的东西永远是原文。** 原文面是全站唯一纯白；一切加工层都比它暗。
2. **批注在物理上无法覆盖原文。** 由版式（主栏/边栏分离）保证，而非由文案提醒。
3. **一种颜色只做一件事。** 颜色 = 状态；动作 = 墨黑；结构 = 明度差。

### 2.5 唯一的"记忆点"：题边刻痕

> 每道题/每个考点在内容左侧固定留出一条 **28px 的「题边」**，用最朴素的计数刻痕记账：
> 在你的全部记录里被问过几次，就刻几道竖线，**每 5 道用一条斜杠收口**；最近这一次是赭色实刻，往上是墨色淡刻。

它为什么是这个产品的：

- **源自题材本身**——面试官在纸上记「正」字、猎头在名单上划道，这是这个场景里真实存在的记录方式；
- **用的是已有字段**——`entries.ask_times`，不需要新增数据、不需要图表库；
- **数据形状天然吻合**——被问频次是离散的、逐次累加的事件，正好是刻痕的形状；
- **解决真问题**——现在这个核心资产是 12px 灰字，肉眼无法比较；刻痕让它随使用时间自然生长，"第三次遇到自我介绍"这件事会比文字更早被看见。

按 skill 的"把大胆花在一个地方"：**全站只有这一个元素允许抢眼，其余一切保持安静和克制。**

## 3. 自我复核：撞了哪几条通用默认，改了什么

按流程，方案初稿必须拿通用默认清单复核一遍并说明修改。逐条结果：

| 通用默认 | 初稿是否撞上 | 修改 |
|---|---|---|
| ① 米白底 + 高对比衬线大标题 + 赤陶点缀 | **差点撞上** | 初稿想让阅读面用暖纸色 `#FAF7F2`（更有"纸感"）。**已改为纯白**——身份不靠背景色，靠**面的明度层级**。且宋体只用于**正文**，不做大标题；赭色只表达"缺口"这一个状态，不做全局点缀 |
| ② 近黑底 + 单一荧光强调 | 否 | 浅色为默认；两个状态色都低饱和，无荧光 |
| ③ 报纸式细线 + 零圆角 + 密集多栏 | **最危险的一条** | ①纸面之间**不用细线分隔**，改用面本身的明度差（`#FFFFFF` vs `#E4E8EC`）；②**保留圆角并让它承载语义**——圆角只给控件；③阅读区**永远单栏**，不做多栏密集排版 |
| ④ 同款圆角卡 + 统一阴影 + 渐变 | 否（这是要删除的对象） | 全站只剩**一级 elevation**（阅读面浮在工作台上）；卡片不再作为通用容器 |
| ⑤ 全大写眉标 / `·` 连元信息 / 按钮都加 `→` | **现在就有，需要清理** | 见 §5「模板化痕迹清理」|

**另外主动删掉的一件配饰**：每张卡片入场都播一次的 `fade + slide-up`。它不传递任何信息，且是模板化的典型特征——只有**回应操作**的动效保留（展开/折叠、保存确认、进度）。

## 4. 逐页改造清单

| # | 页面 | 主要改造 | 工作量 |
|---|---|---|---|
| 1 | **单题复盘** `/interviews/<id>/qa/<qid>` | 样板页。改为「主栏(原文/纯白/宋体) + 批注栏(内凹/无衬线)」；`[字符区间]` 提到段落级、用 tabular-nums；修正入口保持折叠 | ★★★ |
| 2 | **本场复盘** `/interviews/<id>` | 问答对改为连续阅读流，不再一题一张卡；说话人用左侧版式（gutter rule）区分，替代小 chip；**未提取到回答**升级为可点的赭色缺口 | ★★★ |
| 3 | **知识库** `/knowledge` | 引入**题边刻痕**；考点从"卡片流水"改为"按频次降序的账页"；`ask_times` / 出处场次 / 最近时间移入题边注 | ★★★ |
| 4 | **知识点对比** `/compare` | 多次作答改为**错位叠层**（露出日期与场合），展开可并置逐句对照；「标为最佳」用 `--seal` 状态色 | ★★ |
| 5 | **面试记录** `/` | 删 4 个 KPI 卡 → 一句状态行 + 2 个可点状态芯片（点「待确认」直接筛出）；记录卡内部重排：题量成为卡内最强元素，元信息降为次级 | ★★ |
| 6 | **导入面试** `/import` | 保留 ① ②（这是**真实序列**，不是装饰）；原生 `select`/`datetime` 日历图标接入统一控件样式；解析结果的角色确认表沿用新表样式 | ★ |
| 7 | **模拟面试** `/mock`、`/mock/<sid>`、`/mock/<sid>/report` | 作答区用原文面同款（宋体、大行高）以匹配"口述转文字"的场景；报告页的"逐题对照"复用双栏 | ★★ |
| 8 | **设置** `/settings` | 删装饰性 ①②③，改为「左标签 / 右控件」定义列表；模型模式（本地↔云端）做成整页唯一有辨识度的控件，选中即显示后果 | ★ |

**深色主题**：不是反相，需单独设计为**墨底纸栏**（原文用 `#E8E3DA` 而非纯白，边栏反而更暗）。这是本次唯一需要重做、不能沿用变量的部分。

**移动端**：≤640px 时批注栏**移到原文下方**（保持左对齐、保留内凹面），而不是并排压缩；原文行长自然收缩即可，不需要为移动端单独排版。

## 5. 模板化痕迹清理（可加 grep 断言防回归）

1. 页脚 `AI_Review · v0.5.0 · 本地运行 · 数据保存在项目 data/ 目录` → 改成一句正常的话读出来（例如"数据都在本机 data/ 目录，备份就是复制它"）
2. 模型徽标 `AI 模式 · deepseek-ai/…` → 去掉间隔号，改为两行或直接显示短名
3. 按钮/链接尾部的 `→` 全部删除（创建并解析 →、查看对比 →、知识库对比 → 等）

## 8. 风险与取舍（如实披露）

| 风险 | 影响 | 应对 |
|---|---|---|
| **宋体在小字号屏幕发虚** | 若发虚会从"有质感"掉到"糊" | 原文 15.5px 起步 + 本机 ClearType 实测；回退栈保证不崩；不达标则退回黑体但保留"面分层" |

## 9. 评审过程中的一处方法论更正（供参考）

视觉评审工具报告「设置页/导入页底部 x≈305 处有一条白色硬边，把第三个按钮切掉了」，并称在 3 个页面复现。

我用 PNG 像素解码复核（`scripts/_png_check.py`）后确认**这是误报**：

- `10_settings.png` 最底行（y=819）只有 2 处跳变（x=56 页面底→卡边框、x=57 边框→白），**从 x=57 到右边缘整行都是纯白**，不存在 x≈305 的面边界；
- y=800 处 x=304 的跳变是第三个按钮**文字字形**的边缘，不是面边界；
- `04_single_qa.png` 底行的跳变在 x=711/712 与 x=1123/1124，正是设计中的双栏接缝与右卡边缘。

结论：该"缺陷"来自评审工具的图像预处理，**不应写入改造清单**。这也说明视觉模型的像素结论必须用独立手段复核。

## 10. 需要你拍板的三个问题

1. **是否采纳「边注本」方向？**（备选方向见下）
2. **原文是否接受改用宋体？** 这是整套方案最大的观感变化，也是辨识度的主要来源；如果你更希望保持黑体，我会保留"面分层 + 题边刻痕"，但辨识度会明显下降。
3. **分阶段推进还是先做一个样板页？** 我建议**先只做「单题复盘」一页**给你看效果，满意再推全站。

### 备选方向（若「边注本」不合意）

- **方向 B · 时间轴/声纹稿**：把 58 分钟压成顶部一条时间轴，每题是轴上的区间，停顿是真实的空隙；逐字稿按说话时长伸缩。优点是停顿与说话人不再靠 chip；**风险**：依赖转写稿必须有可靠时间戳，缺失时会退化成装饰性进度条。
- **方向 C · 答案台账**：知识库做成 60/40 账页——左侧多次作答错位叠层，右侧行会式频次计数（每 5 次一道斜杠），最佳作答盖一枚印戳。**风险**：与"报纸式细线分栏"距离最近，且主要只适配知识库，需要接受产品内存在两套视觉语言。

### 11.2 与方案的偏离（如实记录）

1. **对比页「作答叠层」的形式做了调整**：方案原意是把多次作答做成错位叠层**替代**表格。实际做成「叠层 + 表格」并存——表格上方加了一排错位堆叠的小纸片（每答过一次多一张，露出日期与来源，最佳作答加松绿顶边），表格继续承担横向比对。理由：这个页面的职责就是对比，叠层一旦替代表格就看不出差异了；而且 `smoke_e2e` 明确断言了「来源面试 / 忠实原文回答 / 优化建议」这几个表头文字。叠层负责「表达累积的厚度」，表格负责「看清差异」。
2. **「最新一次用赭色实刻」没做**：需要「每次被问」的发生记录，而 `ask_times` 只是计数。不愿编造数据，记号统一用墨色。
3. **题边记号从「竖线+斜杠」改成「正」字**：原方案是西式 tally（4 竖 + 1 斜杠）。实现后视觉评审连续两次**数错**（把 12 次读成 7 次、5 次读成 3 次，且始终没看见斜杠）；我用 PNG 逐像素解码证明渲染本身是对的（12 = 4竖+斜 ×2 组 + 2竖），但 ASCII 放大显示斜杠穿过竖线时会粘连成块——**评审数错恰恰是「看不清」的证据**。改用中文记数的「正」字：一眼就是 5，不用数，也更贴题材。
4. **阶段四的两项补做完成**：设置页已改为「左标签 / 右控件」定义列表（三组设置合成一张纸，不再是三张同构白卡）；导入页与全站的原生控件已统一（select 换自绘 chevron、datetime 日历图标深色反相、文本类控件统一 40px 高）。
5. **`--maxw-read` 由 680px 收到 655px**：验收探针在 768px 宽度下测出原文行长 40.5 全角字，超出 ≤40 的目标。

### 11.4 过程中修掉的真实缺陷（不只换肤）

- **宋体在 15.5px 下发虚**：实测着墨量只有黑体的 68%（249 vs 364）。先加 500 字重（+15%），仍偏细；最终**把原文提到 16.5px**（横画细于 1px 时抬字重救不回来，只能给足像素）。
- **底色变深后 `--muted` 掉到 3.98:1**（7 处违规）→ 改为 `#5f6873`，白底 5.65 / 工作台 4.94 / 次级面 4.60。
- **深色主题：栏目标题下划线误用文字墨令牌**，`--ink` 在深色下是骨白，渲染成一条 2px 刺眼白线 → 新增 `--rule / --rule-strong` 结构线令牌。
- **深色三面明度差不足**（1.10:1 / 1.07:1）→ 拉开到 1.22:1 / 1.13:1，并让顶栏比纸面暗，把「最亮的面」还给原文。
- **深色占位文字仅 3.01:1** → 补深色 `--placeholder`。
- **原生 radio/checkbox 仍是系统蓝** → `accent-color` 收进墨黑。
- **对比表「优化建议」列被挤到 66px**（连四个字都放不下、表头折行）→ `table-layout:fixed` + `colgroup`。
- **批注框用等宽字体排中文** → 改无衬线，等宽只留给转写稿与代码。
- **`select` 的自绘 chevron 被 `background` 简写清掉**（阶段五才发现）：`input,select,textarea{background:var(--surface)}` 的简写会重置 `background-image`，导致全站所有下拉框**没有下拉线索**、看起来像普通文本框。改为 `background-color`，并把 chevron 规则移到其后；已用 PNG 像素解码确认箭头实际渲染出来（x≈949–959 处有清晰的 V 形）。
- **日期框比同行输入框高 2px** → 文本类控件统一 `height:40px`（排除 checkbox/radio/range/file/color）。
- **页面顶部留白偏紧**（H1 距顶栏仅 11px）→ `main` 上内边距 24px → 32px。

### 11.5 顺带修掉的两个自检工具缺陷

1. **截图拍到动画中途**：卡片有 0.18s 入场淡入，不加 `--virtual-time-budget` 会拍出半透明「褪色」页面，导致像素审计误判对比度。已修（并最终删掉了入场动画本身）。
2. **移动端截图是假证据**：Windows 上 Chrome headless 的窗口宽度**有 512px 下限**——`--window-size=390` 时页面其实按 512px 排版、截图却裁成 390px，拍出「右侧被切掉」的假象（实测真实横向溢出为 **0**）。改用固定宽度 iframe 包裹（`data:` URL 会被 Chrome 拒绝加载 http 子框架，必须落成 `file://`），并加了「输出 <8KB 即判失败」的空图保护。

### 11.6 一次事故与恢复（供后续参考）

有一轮我用 PowerShell 写 `$edits = @( @("旧","新") )`，**只有一个元素时该嵌套数组会被摊平**，循环变量退化成字符串，`$pair[0]` 取到首字符 `.`、`$pair[1]` 取到 `s` —— 于是对整个 `style.css` 执行了全局 `.` → `s`：259 个类选择器全部失效。

- **发现**：比对 git HEAD，当前文件点号数为 **0**（HEAD 有 330 个）。
- **恢复**：从 Chrome 的 HTTP 缓存里取到改造后的完好副本（`screenshots/.profile/.../f_00006a`，39.6 KB，含全部阶段成果、0 个坏选择器），还原后重新应用那一次本意的改动。
- **防线**：`smoke_e2e.py` 增加样式表完整性断言（类选择器 ≥150 行、`--paper/--margin/--desk` 各 2 处、花括号配对），这类静默破坏以后跑一次自检就会红。
